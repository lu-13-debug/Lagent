# 当前本机 MODex 的可借鉴优点

调查日期：2026-11-02。参考目录：D:\codex\Modex-MH-Agent。

## 版本与证据边界

resources/app/dist/build-info.json 标记 version/display_version=3.0.0，built_at=2026-10-22T16:01:36.720Z。没有上次安装文件内容快照，不能判断每项是否为版本新增，也不能称为官方最新版本。

本轮只读可读Python、模板和浏览器测试脚本，未运行MODex、读取用户数据库、调用模型或反编译pyd/pyc。工具代码体现的是设计与实现意图，未执行其完整产品链路，不将脚本存在称为端到端验收通过。

## 1. 单一数据口径贯穿多个环节

来源：resources/app/tools/survey_schema.py 的模块说明、SCHEMA_ID、normalize。

问卷结构、变量编码、测量尺度、跳转和质量阈值由共用schema提供，导入、清洗、渲染等读取同一份规则。代码还处理阈值误写层级的问题，并明确冲突时采用哪一层。

对DataAgent的启发：在已有阶段合同之外，增加贯穿导入/分析/绘图/报告的指标目录。每个指标统一声明来源、过滤、去重、分母、时间窗口、单位、缺失语义和版本，页面直接读这一目录。不要让不同Skill各自重写口径。

## 2. 分层清洗，保留逐条理由与人工决定

来源：survey_clean.py 的状态、规则和人工复核逻辑说明。

区分有效、无效、待复核和非调查对象，保留理由；人工决定带理由，并限制它能覆盖哪些状态。有效率与有效回收率使用不同分母，避免同名数字其实含义不同。

可借鉴机制：DataAgent的质量问题分成阻断、排除候选、需人工确认和仅提示，保留规则版本、源行定位、处理前后数量及决定。问卷特定的同选阈值不能直接套到游戏或交易数据；“全部相同”不天然代表脏数据。

## 3. 来源登记、隐私隔离和演示数据标记一起设计

来源：survey_import.py 的导入输出与演示模式说明。

输出列映射和PROVENANCE；明确处理跨文件重复，识别私人信息列并隔离；模拟数据进入专用模式，并向下游和导出传播演示标记。

DataAgent已经有字段白名单和示例标识，下一步值得补完整来源链：文件hash→工作表/源行→映射→派生版本→指标→图表→PDF。演示标记应是服务端数据属性，不能靠报告作者记得写一句话。

## 4. 分析计划能驱动确定性方法

来源：survey_methods.py 的调度说明与row_vars/_numeric等实现。

ANALYSIS_PLAN条目指定方法，脚本计算数字，模型负责选方法和解释；方法还有变量角色、编码、适用输入和结果诊断，不仅是调用一个函数名。

DataAgent可以逐步建立方法注册表：适用目标、变量类型、最小样本、前提检查、参数schema、结果schema、诊断和不适用原因。优先实现当前业务需要的期间比较、分组比较、成熟留存、异常检查；Kano/PSM/SEM仅是问卷领域例子，不宜为增加数量而照搬，也未在本轮验证其统计正确性。

## 5. 审查状态诚实，审查结果绑定具体内容版本

来源：vision_ledger.py 的classify、file_hash、RULES_VERSION、状态和预算实现。

区分pass、issue、unreviewed；空响应和服务不可用不当通过。审查以规则版本及文件内容hash登记，支持复用、有限重试和同轮服务不可用熔断，界面与最终审查读取同一清单。

DataAgent宜增加独立ReviewReceipt：内容版本、规则版本、审查类型、结论、问题和未完成原因。PDF能生成不等于视觉审查通过。自动检查核对数值/图源，渲染检查核对中文字体、裁切、图例和长表；视觉模型可选，不可用时诚实标未审查，不默认追加付费请求。

注意参考脚本自身说明：汇总命令在只有unreviewed时可能返回0，因此不能只看进程退出码判“审查通过”；应读取结构化状态。

## 6. “验收现有产物”与“继续运行AI”分开

来源：tools/qa_chat_stage_browser.mjs 中stage fixture、accept请求与409分支。

浏览器测试设计中，验收携带产物snapshot；版本变化返回409，不自动重跑；已有材料recorded不等于结论已独立核验。验收登记也不自动执行下一阶段。

DataAgent当前有stepId防止误批准下一步，可进一步绑定analysisContractHash、artifactHash和scopeVersion。按钮应明确区分“认可当前结果”“修改后重新分析”“继续下一阶段”，避免查看结果就触发模型费用。

这里只确认测试脚本表达的交互契约，未据此推断编译后端的完整实现。

## 7. 硬规则与语义审阅分工

来源：paper_data_check.py 的设计说明、数据清单、独立回执，以及paper_source_scope.py的活动来源解析。

确定性脚本准备当前生效来源和数据材料，查格式硬规则；模型审阅数字在自然语言中的意义，原始JSON保持权威，禁止为了匹配正文反改数据。审查回执独立保存，不靠修改已编译正文登记状态。

对DataAgent上一轮的修正启发：保留结构化证据/单位/期间校验，但不能把任何数字正文都永久限制为fact原文逐字复制。百分比、百分点、合法单位转换、舍入和期间对比应先有确定性变换记录，再允许模型组织文字；无法验证的变换标未核验。模型语义审阅补充因果措辞与解释质量，不能替代数值检查。

## 8. 小型真实交互回归覆盖状态边界

来源：qa_chat_stage_browser.mjs、qa_chat_materials_browser.mjs等可读测试脚本。

值得学习的是用具体交互测试延迟、版本变化、待核验、验收行为及页面错误，而非只确认“节点全部完成”。DataAgent已有浏览器测试，下一步可以补双标签页修改后的旧确认拒绝、PDF旧版本缓存失效、人工清洗决定传播，以及供应商不可用时未审查状态。

## 建议优先顺序

| 优先级 | 借鉴点 | 对现有DataAgent的直接价值 |
| --- | --- | --- |
| 第一批 | 统一指标目录、snapshot确认、来源登记 | 减少口径漂移、误批准和旧产物混入 |
| 第二批 | 多态质量决定、独立审查回执与图表/PDF视觉状态 | 提高可解释性，区分结果生成与结果可信 |
| 第三批 | 方法适用性注册表、可验证数字变换 | 增加真正可执行的分析能力，同时保留自然可读报告 |

本轮为研究记录，未修改DataAgent业务代码，未新增依赖或改变工作流行为。

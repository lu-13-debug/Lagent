# 多模型与 Skill 数据分析工作流设计草案

日期：2026-11-01。状态：待用户确认，尚未修改业务功能。

## 1. 已确认目标与当前基础

沿用现有云端账号版，每个账号独立保存模型凭据和工作流配置。用户上传数据、选择分析目标后，软件按阶段读取指定 Skill，使用该阶段选择的模型与思考强度，调用分析工具，最终生成可直接下载的 PDF 报告。

现有基础是 React / TypeScript / Express / SQLite / Electron。云端按账号分配工作空间，已有上传、确定性指标、任务状态、协作确认、取消、失败退款、报告探索与分享。

核对当前源码后的差距：

- `server/accounts.js` 的 Key 保存在内存 Map，按登录会话和接口地址取用；退出或重启后不保留。
- `src/model-profiles.ts` 只保存接口地址、供应商和模型等非敏感档案，没有多凭据持久化。
- `server/workflow.js` 有 10 个固定节点，但只有 report 节点调用模型；现有 Skill 是元数据，尚不是逐阶段加载执行的指令包。
- `server/model-protocol.js` 已有 Anthropic Messages 和 Chat Completions 适配，尚未传入逐节点思考强度，也没有通用阶段工具循环。
- `src/components/ReportView.tsx` 的 PDF 入口调用 `window.print()`，尚无服务端 PDF 文件生成接口。
- 当前工作区有大量既有未提交修改。本需求保留这些代码，不以旧提交替换现状。

## 2. 路线比较

| 路线 | 收益 | 代价与限制 |
| --- | --- | --- |
| A. 兼容现有软件，分三个里程碑升级（推荐） | 保留账号、数据口径、报告和桌面入口；逐步形成完整分析到 PDF 的闭环 | 第一版采用有依赖关系的阶段模板，不做拖拽编排 |
| B. 重建通用 Agent / 可视化工作流平台 | 分支、循环和任意节点组合更自由 | 改造范围大，既有报告、额度与任务恢复都需迁移 |
| C. 接入外部工作流服务 | 可复用第三方编排能力 | 额外部署服务，凭据、账号隔离与执行状态需要跨系统同步 |

推荐 A。开发顺序为“凭据与模型能力 → 阶段 Skill 和工具执行 → 绘图、核验与 PDF”；三个里程碑分别制定实施计划、测试和验收，全部完成才算本次产品目标交付。

## 3. 凭据库与模型配置

区分三个概念：

1. **凭据**：显示名称、供应商、固定接口地址、协议、加密 API Key。允许同一供应商保存多组 Key。
2. **模型配置**：引用某个凭据，指定完整模型 ID、已确认能力和输出上限；一个 Key 可以供多个模型配置使用。
3. **阶段配置**：引用模型配置与 Skill 版本，设置思考强度、超时、工具调用上限和输出预算。

界面提供新增、修改、删除、检测模型、测试连接与设置默认模型。Key 保存后只返回“已保存”和脱敏尾号，不提供查看明文接口。检测模型只读取目录；付费连接测试由用户点击触发。

云端使用 Node crypto 的 AES-256-GCM 加密保存 Key；随机 nonce、认证标签和密钥版本一并存储。账号 ID、凭据 ID、规范化接口地址和协议作为附加认证数据，避免密文跨账号或跨接口挪用。主密钥由部署环境或密钥文件注入，独立于数据库和 Git；缺少或错误时明确提示不可解密，不退回明文保存。部署文档说明主密钥备份与轮换。

持久保存后，正常退出登录、服务重启不会删除凭据。数据库备份只有密文；使用凭据时由服务端按当前账号鉴权后解密。服务管理员掌握主密钥时具有解密能力，此设计不宣称端到端加密。

更换接口地址必须重新输入 Key 或新建凭据；继续使用管理员主机白名单和禁止凭据跨重定向发送的边界。旧会话 Key 仅在用户明确点击保存时迁入凭据库，不从浏览器存储收集密钥。

## 4. 阶段流程与模型分配

默认流程如下。每个 AI 阶段都可以独立选择模型，或继承工作流默认模型；工具阶段标明实际执行引擎。

| 阶段 | Skill 任务 | 工具与产物 | 建议初始强度 |
| --- | --- | --- | --- |
| 数据理解与质量检查 | 解释字段、识别口径风险与缺失项 | 表结构、质量统计、覆盖范围、数据字典 | low / medium |
| 分析计划 | 根据目标选择指标、分析分支与图表任务 | 结构化分析计划、依赖关系与数据需求 | high |
| 数据处理 | 提出并执行可检查的清洗与转换计划 | 派生数据集、规则清单、处理前后差异 | medium |
| 指标与统计分析 | 调用领域指标与统计方法并解释结果 | 指标表、分组表、统计检验及证据 ID | medium / high |
| 图表设计与绘制 | 选择图形、坐标、分组、单位与图注 | 结构化图表配置、SVG / PNG、底层数据表 | medium |
| 洞察与建议 | 依据证据描述变化、限制与后续行动 | 带证据引用的发现和建议 | high |
| 报告撰写 | 整合背景、方法、结果、图表与限制 | 结构化报告、Markdown | high |
| 结果核验 | 核对数字、单位、图文一致性和引用 | 规则校验结果、AI 审核意见、待解决项 | high |
| PDF 排版与输出 | 依据已核验报告排版 | 可下载 PDF、生成状态、内容版本 | 工具执行，无须额外模型 |

现有活跃、新增、留存、商业化、渠道和周内分析保留为“指标与统计分析”的领域子步骤，沿用现有口径。第一版保留当前已开放领域和输入规范；“任意表格自动理解为任意领域”另行设计，不在本次顺带扩展。

数据处理创建派生版本，原数据保留。默认只自动执行不改变业务含义的标准化；删行、填补缺失或改动业务口径先展示影响并要求确认。自动模式遇到这类处理同样暂停，避免自行决定数据含义。

必需节点不能随意跳过；缺表或用户跳过的可选分支保留原因，并从下游模型输入和最终报告中排除。协作模式保留计划与报告前确认，展示的计划必须是实际阶段产物。

思考强度使用统一内部值 `default / low / medium / high / xhigh / max`，用户说的 mid 对应 medium。实际可选范围由供应商、完整模型 ID 和协议共同决定：

- OpenAI Responses 使用 `reasoning.effort`；兼容 Chat Completions 使用 `reasoning_effort`，仅对已确认支持的模型发送。
- Anthropic Messages 使用其模型支持的 `output_config.effort` 和必要的 thinking 配置。
- 其他供应商单独维护适配与能力声明；不把兼容 Chat Completions 当作支持所有推理参数的证明。
- 模型目录不一定提供思考/工具能力。已知模型使用有来源的能力表，未知模型默认只开放默认档位；能力验证必须明确触发，不靠批量付费探测。
- 不支持的强度禁用并说明原因；服务端再次校验。不静默把 max 换成 high。任务保存请求档位和真正发送的参数摘要。

建议强度仅为初始值，不保证模型都支持表中的全部选项。提高强度可能增加耗时和供应商 Token 费用。

## 5. Skill 如何真正参与执行

内置 Skill 包含 `SKILL.md`、版本、适用阶段、输入输出 schema 和允许调用的工具。模型请求实际注入该 Skill 指令以及目标、上游产物和允许的工具，而不是只在界面显示一个 Skill 名称。

提供内置版本和账号私有文本 Skill；允许编辑或导入单个 Markdown 文件，第一版限制为 64KB，不执行其中附带的脚本、Shell 或依赖安装说明。工具权限由服务端注册，Skill 文本不能自行扩大。通用 Skill 内容跨模型使用，供应商特有能力由协议适配层处理；不自动读取开发电脑的私人 Skills 目录。

每次任务冻结工作流、模型 ID、参数和 Skill 文本版本/hash，运行中修改设置影响后续任务。凭据只保留内部 ID/版本引用，明文不写入任务快照或事件；删除/撤销凭据后，未发出的请求停止并明确报错。

每阶段产物包含输入版本、工具运行记录、结果、证据引用、模型用量与校验状态。阶段完成后持久化供下游读取，避免把全部上下文反复拼接。界面展示执行计划、工具操作和结论摘要；不伪造或要求输出模型私有思维链。

## 6. 内置分析工具

“内置软件辅助”采用服务器工具运行环境，桌面客户端无须另装 Python 或办公软件。

- 保留现有 Node 确定性指标引擎，已有收入、留存、日期和币种口径继续由可测试代码计算。
- Python 环境提供 pandas / NumPy 数据处理、SciPy / statsmodels 中已实现的统计方法、Matplotlib / Seaborn 绘图；依赖锁定并随服务镜像部署。
- 第一版通过已注册的命名操作调用这些库，例如分组聚合、缺失统计、受支持的清洗、指定统计检验和标准图表。AI 输出结构化工具参数，由服务端校验后执行。
- 不开放任意 Python / SQL / Shell 执行或自动 pip 安装。命名工具也要在独立受限子进程运行，限制 CPU、内存、执行时间、输出量与工作目录；不传入模型 Key，不允许联网或访问其他账号数据。
- 文件操作仅使用服务端生成的产物 ID，不接受模型提供的任意磁盘路径。取消和超时要终止工具进程并清理临时文件。
- 原始明细保留在服务器；默认给模型发送字段描述、质量统计、聚合表和经筛选的证据。新增或私人字段不能未经筛选进入提示词。

图表从真实产物取数，AI 选择图表方案，绘图工具执行；图中标题、单位、筛选范围、数据源和图注可追溯。第一版覆盖折线图、柱状图、分布图、散点图与留存热力图；缺少必要字段时明确不可生成。

## 7. 工作流引擎与错误处理

每阶段执行“读取 Skill 与输入 → 调用模型形成工具操作/结果 → 校验参数 → 执行工具 → 接回结果 → 校验并保存产物”，模型和工具循环受次数、输出 Token 与时间预算限制。对于不支持原生工具调用的接口，使用受 schema 校验的结构化操作协议；无法稳定返回时明确提示该配置不适用。

模型适配拆分为 Chat Completions、OpenAI Responses 和 Anthropic Messages。优先复用当前网关的主机校验、取消、响应大小限制、错误分类与脱敏。各阶段记录真实用量；供应商未返回的用量显示未知，不编造 Token 或金额。

取消、401、429、超时、工具失败和格式错误都定位到具体节点。默认不自动切换模型/Key；用户明确选择后才能改用其他配置。模型请求只对明确可重试的瞬时故障做有界重试，并显示可能产生额外供应商费用。

服务重启仍按现有语义将未完成任务标记中断并释放冻结额度。用户创建恢复尝试时复用已验证的阶段产物，沿用原始任务记录；不宣称跨重启精确恢复已发出但未落库的外部模型调用。新增 schema 版本兼容旧任务，原报告依然可读。

保留当前每任务冻结 20 试用额度的规则。新任务在分析、核验和首次 PDF 都成功后一次结算；首次 PDF 失败时保留分析产物并按任务失败释放冻结额度。之后的“只重试 PDF”只调用排版器，不重跑 AI、不再次结算任务额度。供应商已发生的费用不能随软件试用额度释放而退还。

## 8. PDF 与界面

服务器提供独立导出作业，以报告 ID 和版本生成 PDF。使用 Playwright / Chromium 渲染受控报告 HTML 模板，随云端镜像准备运行依赖和中文字体；运行时不访问模型返回的外部 URL。所有文案转义，图表来自本站产物。浏览器实例和导出并发设上限，超时销毁并回收资源。

默认输出 A4 中文报告：封面与范围、执行摘要、数据来源和处理、方法与指标、图表和解释、发现与建议、限制、附录。提供页码、图表编号、长表分页；目录按内容长度决定。附录记录使用的模型、强度、Skill 版本和数据口径，不记录 Key 或私人提示原文。

普通页面新增“下载 PDF”，生成中/失败/重试状态可见；仍保留打印和 Markdown。完整报告 PDF 与当前筛选视图导出明确区分，第一版 PDF 默认原始完整报告；分享脱敏策略不能通过导出绕过。

界面在现有结构内调整：

1. 模型与 API 设置升级为“凭据库 + 模型配置”。
2. Skill 页面展示真实内容、版本、允许工具和个人版本。
3. 新建分析/执行计划增加阶段配置表：Skill、模型、强度、预算；可保存账号私有工作流模板。
4. 运行面板展示实际节点、工具、摘要、失败原因与用量；报告页展示图表及 PDF 下载。

首版不引入拖拽 DAG 编辑器，阶段依赖固定、可选分析分支可配置；先让阶段真正独立执行并产出报告。

## 9. 实施与验收分界

| 里程碑 | 交付 | 必须验证 |
| --- | --- | --- |
| 1. 多凭据与模型能力 | 加密凭据库、模型配置、原生强度适配、设置 UI | 多 Key 切换、退出/重启持久、跨账号拒绝、密文认证失败、接口绑定、日志与 API 不泄漏、不支持档位拒绝、旧设置兼容 |

| 3. 图表与 PDF 闭环 | 标准图表、报告组装、核验、服务端 PDF、部署依赖 | 手算样例与图表数据一致、引用存在、中文字体、长表分页、图表不裁切、PDF 内容/页数检查与逐页渲染目检、失败重试不重跑 AI、双账号下载隔离 |

各里程碑执行相应自动化测试、生产构建和浏览器验收。模型协议先用可控 mock 响应验证；用户配置真实 Key 后再进行明确的付费联测，不把 mock 成功称为所有供应商可用。本轮仅设计调查，尚未运行新功能测试。

## 10. 与 Claude Code 共同修改目录

当前环境的 `claude.cmd --version` 已实际运行，返回 `2.1.316 (Claude Code)`。Codex 当前对 D:\datagent 有写权限。Claude Code 可从同一路径启动；其登录状态、模型权限和具体文件写入审批需由该 Claude Code 会话确认，本轮没有启动付费模型会话或自动向它派发开发任务。

用户可以在 PowerShell 执行：

```powershell
Set-Location -LiteralPath 'D:\datagent'
claude
```

两者能修改同一项目，但当前工作区含大量未提交代码，建议在该目录轮流修改；需要同时工作时使用独立 Git worktree，并先为这批现有改动建立可恢复快照。worktree 默认基于提交，不能假定会自动带走当前未提交修改。

后续按文件明确分工，共享本设计、API 契约和验证记录。模型协议、工作流核心、类型定义、package.json / lockfile 等共享文件由同一方集中维护；合并后统一验证。无需安装额外“连接 Codex 和 Claude Code”的插件。

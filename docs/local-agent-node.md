# 本机执行节点

连接云端服务时，桌面端会把自己电脑上装好的 CLI Agent 注册到账号下。注册成功后，你在网页、桌面端或手机 App 里看到的 `Claude Code`、`Codex` 就是**你自己电脑上的那份**，任务在本机执行，结果回传云端。

## 为什么需要它

执行器装在跑服务的那台机器上。云端部署时服务在服务器，服务器上没装 CLI，所以只能看到内置的 Lagent。桌面端连上云端后启动「本机执行节点」，把本机的 CLI 桥接给服务器，云端账号才有多 Agent 可用。

## 工作方式

1. 桌面端连上云端服务后，在后台拉起 `desktop/node-host.mjs`（独立进程，关掉主窗口不影响它）。
2. 节点扫描本机 PATH，找出 `claude`、`codex` 可执行文件。
3. 用你当前登录的会话注册到服务器，拿到一个 180 天有效的节点令牌。
4. 之后每 25 秒长轮询一次任务；领到任务就在本机执行，过程与结果实时回传。
5. 关掉软件或退出登录，节点断开，服务器上的这些 Agent 立刻消失。

## 执行目录

默认是 `~/Lagent Workspace`（Windows 上是 `C:\Users\<你>\Lagent Workspace`），首次启动自动创建。如果任务的 `workspace` 在本机存在，就用那个目录。

## 安全边界

- 节点只接受**你自己账号**创建的工单，别人的任务到不了你的电脑。
- 节点只执行它注册时声明过的 Agent（`claude-code`、`codex`），服务器无法让它跑任意命令。
- 令牌绑定账号与节点 id，节点被清理或令牌过期后必须重新注册。
- 节点进程只监听出站连接，不开任何本地端口。

## 排查

节点日志在 `<userData>/node/node.log`（Windows 一般是 `%APPDATA%\Lagent\node\node.log`），菜单「打开日志目录」也能到。

| 现象 | 原因 |
| --- | --- |
| 云端看不到 `（本机）` Agent | 没登录、没装 CLI，或节点进程没起来；看 node.log 里的「检测到本机 Agent」 |
| 一直显示「等待注册」 | 桌面端还没登录，登录后 10 秒内会自动重试 |
| 任务派下去一直排队 | 节点掉线；服务器 90 秒没收到心跳会收回这些 Agent |
| 执行失败「本机启动失败」 | CLI 本身报错，看 node.log 里的任务行 |

## 当前限制

- 只桥接 `claude` 和 `codex` 两种 CLI；ACP 类执行器（`dsh-acp` 等）还没接。
- 同一账号连多台电脑时，第二台的同名 Agent 会以 `node-<短id>-claude-code` 的形式出现，界面上按同一品牌显示，但选择时要看清是哪台。
- 项目对话里的文件改动落在节点的默认工作目录，不是云端项目记录里的路径。
